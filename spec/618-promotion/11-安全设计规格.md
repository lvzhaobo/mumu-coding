## 1. 安全目标

| 安全目标 | 说明 | 对应合规 |
|----------|------|----------|
| 数据完整性 | 确保促销活动数据不被篡改，优惠券库存准确 | 金融级数据安全标准 |
| 身份认证 | 确保只有授权用户才能访问和操作系统 | ISO 27001 |
| 最小权限原则 | 每个角色只拥有完成任务所需的最低权限 | 安全设计最佳实践 |
| 审计追踪 | 所有操作可追溯，便于安全审计 | GDPR、网络安全法 |
| 防攻击防护 | 防止恶意攻击（如秒杀刷券、SQL注入等） | OWASP Top 10 |

## 2. 认证与授权

### 2.1 认证机制

| 项目 | 规格 |
|------|------|
| 认证方式 | JWT Token + 密码登录 |
| Token 有效期 | Access Token 2小时，Refresh Token 7天 |
| 密码策略 | 最少8位，包含大小写字母+数字+特殊字符 |
| Token 刷新 | 支持静默刷新，有效期内自动续期 |
| 单点登录 | 支持集成企业统一认证 |

## 3. 数据安全

### 3.1 数据分类与分级

| 数据类型 | 安全等级 | 示例 | 保护措施 |
|----------|----------|------|----------|
| 用户敏感信息 | 机密 | 手机号、地址、订单金额 | 加密存储、脱敏显示 |
| 用户优惠券信息 | 内部 | 用户领取记录、使用记录 | 加密传输、访问控制 |
| 活动配置数据 | 内部 | 活动规则、优惠券配置 | 操作审计、版本控制 |
| 订单交易数据 | 机密 | 订单金额、支付信息 | 加密存储、访问日志 |
| 系统配置 | 一般 | 界面配置、参数设置 | 版本控制 |

### 3.2 加密策略

| 场景 | 加密方式 | 说明 |
|------|----------|------|
| 传输加密 | TLS 1.2+ | 所有接口调用必须使用 HTTPS |
| 存储加密 | AES-256 | 敏感字段（如用户手机号、订单金额）加密存储 |
| 密码加密 | BCrypt | 用户密码使用 BCrypt 哈希存储，不可逆 |
| 密钥管理 | Vault/KMS | 密钥通过配置中心管理，定期轮转 |
| 数据库传输 | SSL | 数据库连接使用 SSL 加密 |

### 3.3 敏感数据保护

| 数据类型 | 保护措施 | 脱敏规则 |
|----------|----------|----------|
| 用户手机号 | 存储加密，传输加密 | 显示为 138****8888 |
| 用户邮箱 | 存储加密 | 显示为 xxx***@xxx.com |
| 用户地址 | 存储加密 | 详细地址脱敏显示 |
| 订单金额 | 存储加密 | 正常显示，操作审计 |

## 4. 接口安全

| 防护措施 | 实现方式 | 说明 |
|----------|----------|------|
| 输入校验 | Spring Validation + 自定义校验器 | 所有用户输入进行类型、长度、格式校验 |
| SQL 注入防护 | MyBatis 参数化查询 | 禁止字符串拼接 SQL，使用预编译语句 |
| XSS 防护 | 前端转义 + 后端过滤 | 用户输入内容进行 HTML 转义，输出时过滤危险标签 |
| CSRF 防护 | JWT Token + 同域限制 | 状态变更接口需携带有效 Token |
| 速率限制 | Redis + Token Bucket | 单用户领取接口：5次/分钟；下单接口：10次/分钟 |
| 防刷机制 | Redis 计数 + 验证码 | 高频请求触发图片验证码 |
| 接口签名 | API Key + 时间戳 + 签名 | 外部接口调用需签名验证 |

### 4.1 速率限制规则

| 接口 | 限制规则 | 超出处理 |
|------|----------|----------|
| 优惠券领取 | 单用户 5次/分钟 | 返回 429 状态码，提示"操作频繁" |
| 订单创建 | 单用户 10次/分钟 | 返回 429 状态码，提示"操作频繁" |
| 活动查询 | 单IP 100次/分钟 | 返回 429 状态码 |
| 数据看板 | 单用户 10次/分钟 | 返回 429 状态码 |

## 5. 外部服务安全

| 风险点 | 防护措施 | 验收标准 |
|--------|----------|----------|
| 数据外泄至第三方服务 | 内部部署，不依赖外部 AI 服务 | 所有数据存储在内部数据库 |
| 消息队列安全 | RocketMQ 访问控制 | 仅允许内部服务访问消息队列 |
| Redis 缓存安全 | Redis 密码认证 + 内网访问 | 禁止外网访问 Redis |
| 数据库访问 | 最小权限原则 | 应用账户仅拥有必要的数据库权限 |

## 6. 部署安全

- [x] 生产/开发环境**严格隔离**，数据不互通
- [x] 敏感配置（API Key、密码）通过环境变量注入，不入代码仓库
- [x] 依赖包定期安全扫描（使用 OWASP Dependency-Check）
- [x] 容器镜像安全扫描（使用 Trivy）
- [x] 网络隔离：应用服务仅开放必要端口
- [x] 防火墙规则：仅允许白名单 IP 访问管理后台
- [x] 定期安全漏洞扫描和渗透测试
- [x] 日志集中存储，保留90天

## 7. 安全审计

### 7.1 审计日志

| 日志类型 | 记录内容 | 保留时间 |
|----------|----------|----------|
| 操作日志 | 操作人、时间、操作类型、操作对象、变更内容 | 90天 |
| 登录日志 | 用户ID、登录时间、IP地址、登录状态 | 90天 |
| 访问日志 | 请求路径、方法、状态码、响应时间 | 30天 |
| 异常日志 | 错误类型、错误信息、堆栈、traceId | 90天 |

### 7.2 安全告警

| 告警类型 | 触发条件 | 通知方式 |
|----------|----------|----------|
| 多次登录失败 | 5分钟内失败超过5次 | 邮件 + 钉钉通知 |
| 异常访问模式 | 短时间内大量请求同一接口 | 邮件通知 |
| 权限越权尝试 | 用户尝试访问无权限资源 | 邮件通知 |
| 数据异常变更 | 大量数据被删除或修改 | 即时告警 |

## 8. 应急响应

| 事件类型 | 响应流程 | 责任人 |
|----------|----------|----------|
| 系统入侵 | 隔离受影响系统 → 备份数据 → 调查原因 → 恢复服务 | 安全团队 |
| 数据泄露 | 评估影响范围 → 通知相关用户 → 修复漏洞 → 审计日志 | 安全团队 + 产品团队 |
| DDoS 攻击 | 启用流量清洗 → 限制异常流量 → 监控恢复 | 运维团队 |
| 服务故障 | 切换备用服务 → 排查原因 → 恢复主服务 | 运维团队 |
