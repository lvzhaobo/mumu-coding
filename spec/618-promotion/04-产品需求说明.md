## 1. 愿景与目标

| 03 痛点 | 04 目标 |
|---------|----------|
| 去年大促活动系统崩溃，大量订单无法处理 | 构建高可用促销系统，确保大促期间系统可用性≥99.9% |
| 促销活动配置复杂，运营人员需要IT协助 | 提供可视化活动配置系统，运营人员可自主完成配置 |
| 缺乏活动效果实时监控 | 构建实时数据看板，关键指标延迟≤5秒 |
| 优惠券规则复杂，用户容易混淆 | 简化优惠券类型至3种核心类型，提供智能推荐 |

## 2. 目标用户

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| **运营人员** | 配置促销活动规则、查看活动数据、管理优惠券 | 高频（每日多次） |
| **审核员** | 审核活动配置、发布活动 | 中频（每日数次） |
| **普通用户** | 领取优惠券、使用优惠券、查看订单状态 | 高频（活动期间） |
| **客服人员** | 查询订单状态、补发优惠券、处理用户咨询 | 高频（活动期间） |
| **系统管理员** | 管理用户权限、查看系统日志、维护系统 | 低频（每周数次） |

## 3. 核心业务场景

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 运营配置活动 | 运营登录 → 进入活动配置页面 → 填写活动信息 → 提交审核 → 审核通过后活动生效 |
| SC-02 | 用户领取优惠券 | 用户进入活动页面 → 查看优惠券列表 → 点击领取 → 领取成功通知 → 优惠券存入账户 |
| SC-03 | 用户下单使用优惠 | 用户选择商品 → 加入购物车 → 结算 → 系统自动计算满减/优惠券 → 用户确认支付 → 订单提交成功 |
| SC-04 | 实时数据监控 | 运营进入数据看板 → 查看订单量/销售额/转化率等指标 → 分析数据 → 调整活动策略 |
| SC-05 | 客服处理咨询 | 用户咨询 → 客服查询订单/优惠券状态 → 客服回复用户 |

## 4. 产品规则

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 优惠券类型限制：仅支持满减券、折扣券、免邮券三种类型 | 邮件沟通 |
| R-02 | 单用户领取限制：同一张优惠券每人限领3张 | 邮件沟通 |
| R-03 | 优惠券智能推荐：下单时自动选择最优优惠券 | 用户访谈 |
| R-04 | 活动配置审批：所有配置变更需审核员审批才能生效 | 邮件沟通 |
| R-05 | 操作日志记录：所有配置变更记录操作人、时间、变更内容 | 邮件沟通 |
| R-06 | 优惠券有效期：领取后7天内有效（可配置） | 需求采集 |
| R-07 | 满减计算规则：满X减Y（每满即减，上不封顶） | 需求采集 |

| 实时数据看板 | **P1** | SC-04 |
| 优惠券智能推荐 | **P1** | SC-03 |

## 6. 验收与成功标准（PRD 层）

| 标准 | 度量 |
|------|------|
| 可演示 | 配置一个完整活动从创建到发布的全流程；演示用户领取优惠券并使用的完整流程 |
| 配置效率 | 运营人员从进入配置页面到提交审核，时间≤2小时 |
| 系统稳定性 | 大促期间系统可用性≥99.9%，订单处理成功率≥99.5% |
| 性能指标 | 优惠券领取接口响应时间≤200ms；支持每秒5000 QPS |
| 数据延迟 | 实时看板数据更新延迟≤5秒 |
| 用户体验 | 优惠券使用率提升30%（对比去年同期） |
