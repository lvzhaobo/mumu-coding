### 1.2 架构风格

| 决策 | 选型 | 理由 |
|------|------|------|
| **前后端分离** | Vue.js 3.x + Spring Boot 2.7.18 | 解耦前端展示与后端逻辑，便于独立开发和部署 |
| **部署模式** | 单体应用 | 促销功能相对独立，单体架构开发效率高，便于快速迭代 |
| **分层架构** | Controller → Service → Repository → DB | 清晰的职责边界，便于测试和维护 |
| **事件驱动** | RocketMQ 消息队列 | 解耦订单创建与优惠券核销，提升系统吞吐量 |

## 2. 后端分层结构

| 层 | 文件 | 允许做 | 禁止做 |
|----|------|--------|--------|
| **Controller** | `controller/*.java` | 参数校验、HTTP 状态码处理、traceId注入 | 直接读写数据库、调用外部服务 |
| **Service** | `service/*.java` | 业务逻辑编排、事务管理、结果组装 | 直接处理HTTP请求/响应 |
| **Repository** | `repository/*.java` | 数据CRUD、查询优化 | 业务逻辑处理、调用外部API |
| **Entity** | `entity/*.java` | 数据库实体映射 | 业务逻辑、数据校验 |
| **DTO/VO** | `dto/*.java` / `vo/*.java` | 数据传输对象、视图对象 | 业务逻辑处理 |

## 3. 前端架构

| 项 | 选型 | 理由 |
|----|------|------|
| UI 框架 | Vue.js 3.x | 响应式设计，组件化开发，生态成熟 |
| 构建工具 | Vite | 快速冷启动，支持热模块替换 |
| 状态管理 | Pinia | Vue 3 官方推荐，轻量级状态管理 |
| HTTP 客户端 | Axios | 支持拦截器、请求取消，社区成熟 |
| 样式方案 | SCSS | 支持变量、嵌套、混合宏，便于样式管理 |
| UI 组件库 | Element Plus | 丰富的组件库，开箱即用 |

## 4. 外部服务集成

| 提供商 | 文件 | 配置检测 | 超时 | 错误处理 |
|--------|------|----------|------|----------|
| **MySQL** | `config/DataSourceConfig.java` | 连接池健康检查 | 30s | 自动重连、熔断降级 |
| **Redis** | `config/RedisConfig.java` | ping命令检测 | 5s | 降级到数据库、本地缓存 |
| **RocketMQ** | `config/RocketMQConfig.java` | 心跳检测 | 10s | 消息持久化到本地、重试机制 |

## 5. 数据存储架构

### 5.1 存储演进路线

| 阶段 | 存储 | 变更范围 | 说明 |
|------|------|----------|------|
| **P0（开发测试）** | MySQL 单库 + Redis 单机 | — | 满足开发测试需求 |
| **P1（预发）** | MySQL 主从 + Redis 主从 | 数据库配置 | 提高读性能和可用性 |
| **P2（生产）** | MySQL 分库分表 + Redis Cluster + RocketMQ | 全链路 | 支持高并发、海量数据 |

### 5.2 缓存策略

| 缓存类型 | Key 设计 | 过期时间 | 刷新策略 |
|----------|----------|----------|----------|
| 活动配置 | `activity:{id}` | 5分钟 | 活动更新时主动刷新 |
| 优惠券列表 | `coupons:activity:{activityId}` | 3分钟 | 优惠券发放后刷新 |
| 用户优惠券 | `user:coupons:{userId}` | 1分钟 | 领取/使用后刷新 |
| 热点数据 | `hot:*` | 10分钟 | 定时任务刷新 |

## 7. ADR（架构决策记录）

| ADR | 决策 | 核心理由 |
|-----|------|----------|
| **ADR-001** | 选择 Spring Boot 2.7.18 作为后端框架 | 社区成熟，生态完善，便于快速构建企业级应用，与现有技术栈保持一致 |
| **ADR-002** | 选择 MySQL 8.0 作为主数据库 | 事务支持完善，性能稳定，社区活跃，适合中小型促销活动数据存储 |
| **ADR-003** | 选择 Redis 作为缓存层 | 高性能内存存储，支持多种数据结构，适合热点数据缓存和限流计数 |
| **ADR-004** | 选择 RocketMQ 作为消息队列 | 高吞吐量、低延迟，支持事务消息，适合订单与优惠券的异步解耦 |
| **ADR-005** | 单体架构而非微服务 | 促销活动功能相对独立，单体架构开发效率更高，便于快速迭代和部署 |

## 8. 安全架构

| 层 | 当前措施 | 生产改进 |
|----|----------|----------|
| **认证** | JWT Token | 引入 OAuth2.0，支持多认证方式 |
| **CORS** | 白名单配置 | 细粒度路径控制，支持动态配置 |
| **密钥** | 配置文件存储 | 使用 Vault/KMS 进行密钥管理 |
| **数据加密** | 密码 BCrypt 加密 | 敏感字段传输加密、存储加密 |
| **限流** | Redis + Token Bucket | 引入 Sentinel 进行精细化限流 |
| **日志审计** | 操作日志记录 | 引入审计日志框架，支持实时监控 |
