## 字段说明 — 每条 UserStory 必须包含以下字段

| 字段 | 填写说明 | 数据来源 ← | 流向下游 → |
|------|----------|------------|-----------|
| **需求编号** | 唯一编号，如 REQ-MS-001-001 | ← `02` 采集编号 | → `14` 追踪矩阵首列 |
| **故事** | 作为【角色】，我希望【行为】，以便【价值】 | ← `04` PRD 场景拆解 | → `06` FSD 功能点 |
| **优先级** | P0（必须）/ P1（应该）/ P2（可选） | ← `03` §4 成功标准 | → `12` 里程碑排期 |
| **来源** | 对应 03/04 哪一条需求 | ← `03` 范围 · `04` 场景 | |
| **前置条件** | 触发该故事的前提状态 | ← `04` 用户流程 | → `13` 测试前置 |
| **功能对齐** | 对应功能规格 + 非功能约束 | | → `06` FSD · `07` NFR |
| **设计对齐** | 对应架构、接口、数据、安全 | | → `08` 架构 · `09` API · `10` Data · `11` 安全 |
| **验证对齐** | 对应测试用例 + 追踪矩阵行 | | → `13` TC · `14` 追踪矩阵行 |
| **验收标准** | AC，每条可独立验证 | ← 故事 + `07` NFR | → `13` 测试用例依据 |

## US-001（P0）运营创建促销活动

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-MS-001-001 |
| **故事** | 作为运营人员，我希望创建促销活动，以便自主配置活动规则 |
| **优先级** | P0 |
| **来源** | ← 03 §3 / 04 SC-01 |
| **前置条件** | 运营人员已登录系统，拥有活动配置权限 |
| **功能对齐** | → 06 §2.1 · 07 §2.1 |
| **设计对齐** | → 08 §3 · 09 POST /api/v1/promotion/activities · 10 activity表 · 11 §3 |
| **验证对齐** | → 13 TC-MS-001-001 · 14 第1行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-001-01 | 运营人员进入活动配置页面，可填写活动名称、开始时间、结束时间 |
| AC-001-02 | 运营人员可配置优惠券规则（满减金额、折扣比例、免邮条件） |
| AC-001-03 | 运营人员可预览活动配置效果 |
| AC-001-04 | 配置提交后自动进入审批流程 |
